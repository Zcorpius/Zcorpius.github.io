2. 整体框架类图

  • InputManagerService 位于 Java 层 InputManagerService.java,成员 mNative(NativeImpl)内部 mPtr 指向 Native 层 NativeInputManager 对象——与 6.0 的 mPtr 指向一致,只是中间多了一层接口封装;
  • NativeInputManager 位于 JNI 层,同时实现三个 Policy 接口(Reader/Dispatcher/PointerController),mInputManager 持有 InputManager;mLooper 是 “android.display” 线程的 Looper(PointerController 等 MessageHandler 用);
  • InputManager 是流水线总装:按 Dispatcher → Processor → Blocker → Reader 的顺序构造,前一级(先构造的下游)作为后一级构造函数的 listener 参数传入,形成单向链表式流水线;
  • 数据流 InputReader → UnwantedInteractionBlocker → InputProcessor → InputDispatcher,单向、不共享内部状态——这是 AOSP10+ 相对 6.0 最大的架构变化(源自 ChromeOS input pipeline 的设计)。

2.1 重要类关系:Java / JNI 层

  • InputManagerService(橙)持有 mNative(声明类型为接口 NativeInputManagerService),由内部类 NativeImpl 实现,NativeImpl.mPtr 保存 Native 层 NativeInputManager 对象指针(经 injector 注入,便于测试时替换实现);
  • NativeInputManager(绿)位于 JNI 层,mServiceObj 回指 Java 层 IMS(JNI 上调入口),mLooper 是 “android.display” 线程的 Looper;
  • NativeInputManager 一身兼三职:实现 InputReaderPolicyInterface / InputDispatcherPolicyInterface / PointerControllerPolicyInterface;其构造函数中 new InputManager(this, *this) 并 addService("inputflinger") 注册 Binder 服务;
  • mInputManager(sp<InputManagerInterface>)组合 Native 层总装对象,展开见 2.2。

2.2 重要类关系:Native 层

  • InputManager 双重身份:实现 InputManagerInterface(总装接口)与 BnInputFlinger(Binder 服务端);
  • 四个成员均为接口智能指针(unique_ptr<…Interface>),构造序 Dispatcher→Processor→Blocker→Reader(下游先行,前一级作为后一级构造参数);
  • 接口体系:UnwantedInteractionBlockerInterface / InputProcessorInterface / InputDispatcherInterface 均继承 InputListenerInterface;InputReaderInterface 不继承——它不是被通知方,事件经 mQueuedListener 送往下一级;
  • Reader/Blocker/Processor 三级各持一个 QueuedInputListener(其 mInnerListener 即下一级),flush() 攒批转发;
  • ① InputReader 持 mEventHub(shared_ptr<EventHubInterface>,由 createInputReader() 工厂创建)与 mPolicy(指向 NativeInputManager);
  • ④ InputDispatcher 持 mPolicy(引用)、mLooper、mInboundQueue/mConnections 等(成员细节见第 6 章);
  • 线程载体统一为 InputThread
