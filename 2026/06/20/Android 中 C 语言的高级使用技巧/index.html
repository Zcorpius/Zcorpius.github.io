6. 哨兵模式（Sentinel Pattern）

回到 toolbox.c 的最后一行：

这个 { 0, 0 } 是数组的最后一个元素，全 0（NULL）。它的作用是标记数组结束。

6.1 为什么需要哨兵

C 数组不知道自己的长度。sizeof(arr)/sizeof(arr[0]) 只在定义处有效，传给函数后退化成指针，长度信息丢失。

那怎么遍历？两种方案：

方案 A：传长度参数

缺点：每个调用者都要算长度，容易传错。

方案 B：用哨兵标记结尾

优点：调用者无需关心长度，遍历逻辑自包含。

6.5 哨兵 vs 显式长度

维度 哨兵 显式长度
加新条目 改一处（在哨兵前加） 改两处（数组 + 计数器）
遍历性能 略慢（每次比较 NULL） 略快（计数器递增）
安全性 高（不会越界） 低（计数器算错就数组越界）
数据完整性 数据本身有”结尾”标记 数据本身无标记，靠外部维护

系统编程偏好哨兵——简单、安全、抗人为错误。

7.4 关键设计点

设计点 1：argv[0] 是 dispatch 的唯一依据

Linux execve 不修改 argv——内核只关心加载哪个二进制，不在乎被叫什么名字。软链接的名字原封不动传给新进程。这正是 multi-call binary 能工作的根本原因。

设计点 2：两种调用方式等价

后者通过 toolbox_main 的 main(argc - 1, argv + 1) 巧妙地把 argv 偏移一位，让 argv[0] = "getevent"，然后递归调用 main() 走相同的 dispatch 逻辑。
