1. 前言

Note

无 Binder，不 Android。Binder 是 Framework 中的核心知识，但是翻阅了好些博客，要不是从底层开始讲解，要不就是从架构角度进行讲解，很是晦涩。刚好自己也想把项目的架构自己梳理一边，趁着这个机会从项目搭建开始，从 AIDL 开始从头开始整理，直到 SDK 提供，穿针引线起来。

常见Binder跨进程通信方式主要有两种：

  1. 通过 Service 组建 binderService 方式获取 IBinder 通信。
  2. 通过 ServiceManager.getService 方法，从 ServiceManager 中获取到相关服务对应的 Manager，其实也是 IBinder。

不过第一种其实也是先通过 ServiceManager 获取到对应的 AMS，然后再通过 AMS 相关接口方法传递 IBinder 对象。

在Android系统中，每个进程都运行在一块独立的内存中，在其中完成自己的各项活动，与其他进程都分隔开来。但也有进程应用间进行互动的需求，比如传递数据或者任务委托等，也就是所谓的跨进程通信。

AIDL (Android Interface Definition Language，Android 接口定义语言) 就是为了满足这种需求而诞生的。通过AIDL，可以在一个进程中获取另一个进程的数据和调用其暴露出来的方法， 从而满足进程间通信的需求。

AIDL 是用于定义服务端和客户端通信接口的一种描述语言，可以拿来生产 IPC 代码，从某种意义上说 AIDL 其实就是一个模板，因为在使用过程中，实际起作用的并不是 AIDL 文件，而是据此生产的一个 Interface 的实例代码， AIDL 其实是为了避免我们重复写代码而出现的一个模板。主要介绍一下类型特点：

  1. 文件类型：用 AIDL 书写的文件的后缀是 .aidl，而不是 .java。
  2. 默认支持的数据类型包括：
    1. Java 中的八种基本数据类型，包括 byte，short，int，long，float，double，boolean，char。
    2. String 类型。
    3. CharSequence类型。
    4. List类型：List中的所有元素必须是AIDL支持的类型之一，或者是一个其他AIDL生成的接口，或者是定义的parcelable。List可以使用泛型。
    5. Map类型：Map中的所有元素必须是AIDL支持的类型之一，或者是一个其他AIDL生成的接口，或者是定义的parcelable。Map是不支持泛型的。
  3. 但是上述类型之外的数据类型，在使用之前必须导包，就算目标文件与当前正在编写的 .aidl 文件在同一个包下——在 Java 中，这种情况是不需要导包的。

3.1. bindService 绑定流程

绑定流程如下：

3.1.1. matrixclient 创建 Intent

  • 创建显式 Intent，指定 Server 端的包名和 Service 类名

3.1.2. matrixclient 绑定服务

  • 调用 boolean result = bindService(intent, remoteConnection, Context.BIND_AUTO_CREATE);
  • BIND_AUTO_CREATE 标志表示如果服务未启动，自动创建服务

3.1.3. AMS 处理绑定请求

  • ActivityManagerService (AMS) 是 Android 系统服务，负责管理应用组件的生命周期
  • AMS 检查 MatrixService 是否已启动

3.1.4. AMS 启动 MatrixService（如果未启动）

  • 如果 MatrixServerService 未启动，AMS 创建服务进程
  • 调用 MatrixServerService.onCreate()
    • 创建 MatrixServerBinder 实例

3.1.5. AMS 调用 onBind

  • AMS 调用 MatrixService.onBind(intent)
  • onBind() 返回 mMatrixServerBinder（IBinder 对象）

3.1.6. Binder Driver 传递 IBinder

  • Binder Driver（内核层）负责跨进程传递 IBinder 对象
  • AMS 将 IBinder 对象从 Server 进程通过 Binder Driver 传递到 Client 进程
  • 这是 Binder 机制的核心：跨进程传递 Binder 对象

3.1.7. AMS 调用 onServiceConnected

  • AMS 通过 Binder Driver 跨进程调用 ServiceConnection.onServiceConnected(name, service)
  • 参数 service 就是 MatrixServerBinder 实例的 IBinder 对象

3.1.8. Matrixclient 获取代理对象

  1. AMS 调用 ServiceConnection.onServiceConnected(name, service)
  2. ServiceConnection（MatrixServerConnection）调用 IMatrixProxy.Stub.asInterface(service)
  • asInterface() 方法判断：
    • 如果是本地接口（同一进程），直接返回接口对象
    • 如果是跨进程，返回 IMatrixProxy.Stub.Proxy 代理对象
  • 由于是跨进程调用，返回 IMatrixProxy.Stub.Proxy 对象
  • 将代理对象赋值给 mIMatrixProxy

3.1.9. 绑定完成

  • 绑定流程完成，matrixclient 现在可以通过 mIMatrixProxy 调用 matrixserver 的方法

3.2. setState 流程

3.2.1. Matrixclient 调用

  • 调用 mIMatrixProxy.setState(mInitState)
  • IMatrixProxy.Stub.Proxy.setState() 方法被调用

3.2.2. Matrixclient 准备数据

  • Parcel.obtain() 创建 _data 和 _reply 对象
  • _data.writeInterfaceToken(DESCRIPTOR) 写入接口标识
  • _data.writeInt(state) 写入参数
  • 调用 mRemote.transact(TRANSACTION_setState, _data, _reply, 0) 发送请求
  • 请求通过 Binder Driver 发送到内核层

3.2.3. 跨进程通信

  • Binder Driver（内核层）接收 Client 进程的请求
  • 将请求分发到 Server 进程的 Binder 线程池

3.2.4. Matrixserver 接收数据

  • Matrixserver Binder 线程池 中的某个线程接收请求
  • 调用 IMatrixProxy.Stub.onTransact() 方法

3.2.5. Matrixserver 解析请求

  • data.enforceInterface(DESCRIPTOR) 验证接口标识
  • int _arg0 = data.readInt() 读取参数
  • 根据事务码 TRANSACTION_setState 调用相应的方法
  • IMatrixProxy.Stub.onTransact() 调用 this.setState(_arg0)

Note

关键点：this 指向的是 MatrixServerBinder 实例（因为实际运行时对象是 MatrixServerBinder）

由于多态机制，实际调用的是 MatrixServerBinder.setState(int state)，MatrixServerBinder 更新 MatrixService 的内部状态 mState = state

3.2.6. Matrixserver 返回数据

  • reply.writeNoException() 写入无异常标识
  • Binder 线程将 reply 通过 Binder Driver 返回给 Client 端

3.2.7. Matrixclient 接收返回

  • reply.readException() 读取异常信息（无异常则继续）
  • reply.recycle() 和 data.recycle() 回收 Parcel 对象
  • MainActivity 的 setState() 调用完成

3.3.getState 流程

3.3.1. Matrixclient 调用

  • 调用 mIMatrixProxy.getState()
  • IMatrixProxy.Stub.Proxy.getState() 方法被调用

3.3.2. Matrixclient 准备数据

  • Parcel.obtain() 创建 _data 和 _reply 对象
  • _data.writeInterfaceToken(DESCRIPTOR) 写入接口标识
  • （getState 无参数，无需写入参数）
  • 调用 mRemote.transact(TRANSACTION_getState, _data, _reply, 0) 发送请求
  • 请求通过 Binder Driver 发送到内核层

3.3.3. 跨进程通信

  • Binder Driver（内核层）接收 Client 进程的请求
  • 将请求分发到 Server 进程的 Binder 线程池

3.3.4. Matrixserver 接收数据

  • Matrixserver Binder 线程池 中的某个线程接收请求
  • 调用 IMatrixProxy.Stub.onTransact() 方法

3.3.5. Matrixserver 解析请求

  • data.enforceInterface(DESCRIPTOR) 验证接口标识
  • （getState 无参数，无需读取参数）
  • 根据事务码 TRANSACTION_getState 调用相应的方法
  • IMatrixProxy.Stub.onTransact() 调用 this.getState()

关键点：this 指向的是 MatrixServerBinder 实例（因为实际运行时对象是 MatrixServerBinder）

由于多态机制，实际调用的是 MatrixServerBinder.getState()，MatrixServerBinder 返回 MatrixService 的内部状态 mState

3.3.6. Matrixserver 返回数据

  • int _result = this.getState() 获取返回值
  • _reply.writeNoException() 写入无异常标识
  • _reply.writeInt(_result) 写入返回值
  • Binder 线程将 reply 通过 Binder Driver 返回给 Client 端

3.3.7. Matrixclient 接收返回

  • _reply.readException() 读取异常信息（无异常则继续）
  • int _result = _reply.readInt() 读取返回值
  • _reply.recycle() 和 _data.recycle() 回收 Parcel 对象
  • IMatrixProxy.Stub.Proxy.getState() 返回 _result
  • MainActivity 的 getState() 调用完成

3.4. IMatrixProxy.Stub.Proxy 与 IMatrixProxy.Stub 的区别

3.4.1. IMatrixProxy.Stub.Proxy（Client 端代理）

  • 位置：运行在 Client 进程中
  • 作用：封装跨进程调用的细节，提供本地接口
  • 实现：每个方法都调用 transact() 通过 Binder Driver 发送请求
  • 获取方式：通过 IMatrixProxy.Stub.asInterface(service) 获取
  • 继承关系：实现 IMatrixProxy 接口，但不继承 Binder

3.4.2. IMatrixProxy.Stub（Server 端基类）

  • 位置：运行在 Server 进程中
  • 作用：作为 Server 端的基类，处理来自 Client 的跨进程请求
  • 实现：onTransact() 方法解析事务码并调用子类实现的方法（通过多态）
  • 继承关系：继承自 android.os.Binder，实现 IMatrixProxy 接口
  • 使用方式：Server 端继承此类并实现业务逻辑
特性 IMatrixProxy.Stub.Proxy IMatrixProxy.Stub
位置 Client 进程 Server 进程
作用 发起跨进程调用 处理跨进程请求
继承关系 实现 IMatrixProxy 接口 继承 android.os.Binder，实现 IMatrixProxy
关键方法 transact() 发送请求 onTransact() 处理请求
获取方式 IMatrixProxy.Stub.asInterface(service) Server 端继承此类
是否持有 Binder 持有远程 Binder 对象引用 本身就是 Binder 对象
this 指向 Proxy 实例 子类实例（如 MatrixServerBinder）

4. AIDL 关键词：in、out、inout、oneway

in、out、inout 是 aidl 中的 directional tag，表示了在跨进程通信中数据的流向：

  • in 表示数据只能由 客户端流向服务端 ，服务端会获取到客户端完整的数据，但 客户端不会同步服务端对该对象的修改 ，不写的话，默认的 tag 就是 in。
  • out 表示数据只能由 服务端流向客户端 ，从服务端端接受该对象不为空，但字段内容为空， 服务端修改对象后，binder 远程调用返回后，客户端会收到修改后的对象 。
  • inout 则表示数据可在 服务端与客户端之间双向流通 。

Note

默认情况下，我们在 AIDL 中定义的接口方法是同步的，如果 AIDL 中的接口方法被 oneway 修饰了，那么这些方法就变成 异步 ，被 oneway 修饰了的方法不可以有返回值，也不可以有带 out 和 inout 的参数。

Note

为什么需要添加 readFromParcel(Parcel in) 方法？

readFromParcel不是Parcelable接口的标准方法，但AIDL需要它来支持out和inout参数：

  • in参数：使用CREATOR.createFromParcel()创建新对象
  • out参数：创建空对象，然后用readFromParcel()更新
  • inout参数：先用CREATOR读取，再用readFromParcel()更新返回值

在AIDL生成的代码中，会调用value.readFromParcel(_reply)来更新已存在的对象，而不是创建新对象。

6. 死亡通知

死亡通知是为了让 Bn 端(服务端进程)能知晓 Bp 端(客户端进程)的生死情况，当 Bp 端进程死亡后能通知到 Bn 端。

Note

定义：AppDeathRecipient 是继承 IBinder::DeathRecipient 类，主要需要实现其 binderDied() 来进行死亡通告。注册 binder->linkToDeath(AppDeathRevipient) 是为了将 AppDeathRecipient 死亡通知注册到 Binder 上。

Bn端只需要覆写 binderDied() 方法，实现一些后续清楚类的工作，则在 Bp 端死掉后，会回调 binderDied() 进行相应处理。如果不做，就会留下僵尸引用。
