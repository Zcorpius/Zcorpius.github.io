记忆方法

发表于 2026-05-16 | 分类于 Tool
字数统计: 2.1k | 阅读时长 ≈ 7

由于梳理新的技术博文时发现之前的内容基本忘得差不多了，随着年纪的增长记忆也越来越困难，很是烦恼，干脆和AI进行了记忆方法的探索，把记忆方法也梳理成博文。以 Binder 模块为试验对象，探索适合源码类笔记的记忆方法。本文是迭代稿，边试边改。

1. 问题:为什么读了多遍还是记不住

  • 重读产生的是熟悉感,不是回忆能力。读的时候觉得”都懂”,放下就忘。
  • 笔记结构太好(调用树、对比表),每次阅读都是结构在替自己撑着逻辑——这是”识别”,不是”重建”。
  • 笔记按源码流组织,不按问题组织。陈述句读起来顺,读完就忘;记忆需要问题做钩子。
  • 集中重复没有间隔,效率远低于分散提取。

对既有笔记的诊断:编码质量已经不低(对比表 = 对比编码,配图 = 双编码,callout = 精细编码),缺的是整个”提取”环节——从来没有”不看笔记、凭记忆输出”的动作。

2. 心智模型:记忆不是硬盘

Bjork 夫妇的区分:

概念 含义 什么能抬高它
存储强度 长期痕迹有多牢 部分遗忘后,带一点费力地成功提取
提取强度 此刻想不想得起来 重读(短暂有效,所以产生错觉)

两个反直觉结论:

  • 遗忘不是故障,是记忆的筛选器。好方法不是阻止遗忘,而是把提取安排在”快忘掉”的边缘。
  • 学习时的顺畅感和留存率大致负相关。读第五遍已经毫不费力,那一遍几乎不产生巩固。

推论:记忆效果 ≈ 编码时连得多深 × 之后成功提取了几次,和”输入(读)了几遍”关系很小。

3. 三个核心杠杆

认知心理学里效应量最大、被反复验证的三个,其他技巧基本都是变体:

  1. 提取练习(testing effect):考自己 > 读答案。
  2. 间隔(spacing):同样 60 分钟,分散在 3 天远好于一天内 3 遍。
  3. 精细编码(elaboration):问”为什么”、和已知对比、自己举例。

4. 分层总结:先搭地图,再展开

先总览后展开有学习科学依据:Ausubel 的先行组织者(advance organizer)——学细节前先给一个高层框架,理解和留存都显著提升。专家和新手的差距也主要在这层组块(chunking)组织,而非记忆力本身。

层级 内容 记忆标准
L0 全领域模块图 Binder 分几个模块,每个一句话 必须能默写(它是索引)
L1 模块骨架 每篇笔记 3~5 句进行总结 能叙述出来
L2 细节 笔记正文 知道在哪、30 秒能查到

三条规则:

  1. 按问题划分,不按源码文件划分。模块名最好本身就是问题(“怎么起来””服务怎么注册”),问题才是记忆的钩子。

  2. 总结必须合上原文写。产物不是重点,动作才是:

    1. 合上写 = 生成 + 提取;
    2. 开着压缩 = 高级重读，写不出来的地方才是要补的。
    3. 警惕”无限整理笔记”——它感觉像学习，本质还是输入侧工作。

  3. 模块图本身也是结构知识。这是第一个要默写的对象；且不用等地图完美才开始提取练习，画地图这个动作就应该半凭记忆完成。

现有笔记天然就是模块。v0 草图按“一次服务的生命周期”组织,模块归属待逐篇凭记忆校对:

4.2 展开:从地图到骨架(L0 → L1)

每个模块产出 3~5 句话。合格标准：每句都是生成器 。看着它能重新推出这一块的调用树或因果链。

反例是”正确的废话”,比如”Binder 启动涉及多个进程”：压缩了,但解不开。

骨架句天然分三类,正好对接第 5 节的知识类型:

骨架句类型 作用 例子(取自 Binder启动)
结构句 能推出调用树、层次 事件循环四层:joinThreadPool → getAndExecuteCommand → talkWithDriver(ioctl) → executeCommand
因果句 能推出”为什么” fork 只复制用户态的 fd 和内存，驱动的 binder_proc 不会跟过去，所以子进程必须关闭继承的 fd，重新初始化
特例句 用反差锚定主线 servicemanager 反例:不开线程池，主线程 Looper 直接轮询 Binder fd

数字类任意事实（15+1、bwr 六字段、BC/BR 全表）不进骨架。因为推不出来，可以走第 5 节的卡片线。

写骨架的流程:

  1. 合上笔记：凭 L0 地图里那一句 + 已有记忆写 3~5 句。写不全是正常信号，空着的就是缺口。
  2. 翻开校对：错的改、漏的补、多的删。校对动作本身就是一次提取练习。
  3. 此后间隔复习的默写对象就是这 3~5 句，不再重读全文。

按模块状态选起点:

  • 已梳理透的模块(如 Binder启动)：直接合上写，校对成本低，先做攒正反馈。
  • 还没吃透的模块(如 Driver 探索)：先读 ，然后合上写，终点同样是那 3~5 句。

一次只展开一个模块,不要一天做完五个。

4.3 示例:Binder启动 的 L1 骨架(v1)

  1. 三条路径的判据：是否执行本进程的 app_main.cpp::main()
  2. ProcessState = 进程级（open 驱动 + mmap + 15+1 线程上限）；IPCThreadState = 线程级（TLS）
  3. 事件循环四层:joinThreadPool → getAndExecuteCommand → talkWithDriver(ioctl) → executeCommand
  4. isMain:BC_ENTER_LOOPER（用户态主动）vs BC_REGISTER_LOOPER（驱动 BR_SPAWN_LOOPER 催的）
  5. 两个特例：servicemanager 用 Looper polling 不开线程池；HW Binder 是另一套 hardware::ProcessState

4.4 各模块骨架进度

其余模块留空是故意的：骨架必须自己合上写。别人（包括 AI）代写，就退化成“读别人的总结”，生成环节消失，又回到重读老路。

  • 全景 / 剖析之旅
  • 启动初始化 / Binder启动 → 4.3
  • 启动初始化 / Servicemanager启动
  • 服务管理 / Servicemanager获取、setService、getService
  • 通信全流程细节 / framework层分析
  • 使用 / Binder使用、AIDL剖析
  • 驱动层 / Driver 探索

5. 按知识类型选方法

源码笔记里混着三类知识,最优方法不同。不分类型、一套方法怼上去,是记忆失败的直接原因。

知识类型 Binder启动.md 里的例子 最优方法
结构关系 调用树、四层循环嵌套、三条路径 合上笔记重建：默画树、默写表
因果理由 为什么 fork 要防护、mIn 没消费完为什么不读新的 自问为什么：先口头答，再翻笔记对
任意事实 15+1、bwr 六字段、BC/BR 命令名 间隔卡片(Anki)，顽固的再上助记术

逻辑:

  • 结构关系可以推导——骨架记住了,细节能现场重演,所以练”重建”。
  • 任意事实没有逻辑可推导,只能靠排期重复。
  • 因果知识是面试和排查问题时真正拉开差距的部分,靠自我解释留下痕迹。

“记住”的标准见 4.2；能默写各模块的 L1 骨架即可。其余(BR_* 全表、bwr 六字段、饥饿检测细节)定位为”知道在哪、30 秒能查到”，不进记忆负担。

6. 两个放大器

6.1 应用实践

应用 / 多情境。 挂在真实体验上的记忆线索比纯文字丰富一个量级:

  • 真机上 ps -T 看每个进程的 Binder:pid_N 线程。
  • 写个 demo 并发调用，亲眼看线程数往 16 涨。
  • logcat 里抓一次 binder 线程池告警。

见过一次的东西和读过十遍的东西,不是同一种记忆。

6.2 自我阐述

讲出来(Feynman)。 讲 = 提取 + 生成 + 精细编码三合一，且语言必须线性化，一开口缺口立刻暴露。不需要听众，对着手机录 10 分钟，回听哪里卡壳、哪里只能背原话，那里就是假懂。
