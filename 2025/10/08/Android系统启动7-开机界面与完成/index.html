Android 系统启动：从开机动画到桌面就绪

源码基线：本地 LineageOS 22.2 / Android 15 的 frameworks/native/services/surfaceflinger、frameworks/base/cmds/bootanimation 和 frameworks/base/services。本文接在 system_server 的 systemReady() 与应用进程创建之后，追踪画面如何出现，以及 framework 如何宣布启动完成。设备形态、用户模式和厂商实现会改变 HOME 的选择与可见时序。

1. 先区分四个“完成”

启动后半程有两条并行的线，最后在窗口就绪处交汇：

显示线：init 启动 SurfaceFlinger → SurfaceFlinger 请求 init 启动 bootanimation → bootanimation 向 SurfaceFlinger 提交画面 → WMS 等待可显示的窗口并结束动画 → SurfaceFlinger 收到 bootFinished()。

应用线：system_server 启动 AMS/ATMS/WMS 等服务 → AMS systemReady() → ATMS 发起 HOME Activity → 应用进程启动、绘制窗口并进入 idle → AMS 完成 framework boot phase，安排用户的开机广播。

不要把下列事件画成同一个时间点：

事件 表示什么 不能据此断言
systemReady() AMS 已允许启动真实应用，并开始 HOME 等后续工作 桌面已经绘制
service.bootanim.exit=1 请求开机动画自行退出 动画进程已经退出、屏幕已经启用
SurfaceControl.bootFinished() WMS 告知 SurfaceFlinger 启动显示阶段结束 每个用户都已解锁、每个应用都收到广播
sys.boot_completed=1 AMS 的 finishBooting() 到达设备级完成点 ACTION_BOOT_COMPLETED 的所有接收者都执行完毕

2. SurfaceFlinger 是独立的显示服务

surfaceflinger.rc 将 /system/bin/surfaceflinger 声明为 init service，属于 core animation 类。它与 Zygote、system_server 不是父子关系，也不是 system_server 里的 Java 服务。main_surfaceflinger.cpp 创建并初始化 SurfaceFlinger 后，向 servicemanager 发布 SurfaceFlinger 和 SurfaceFlingerAIDL 服务，再运行主循环。

SurfaceFlinger 负责图层合成与显示提交。开机动画、SystemUI、HOME 和普通应用都可以是画面来源；WMS 决定窗口组织与显示启用的时机，SurfaceFlinger 负责把这些图层合成为可呈现的帧。因而“SurfaceFlinger 启动”与“桌面可见”之间仍有一段相当长的依赖链。

3. 开机动画如何启动与退出

bootanim.rc 把 bootanimation 声明成 disabled、oneshot 的 init service。它不会仅因为所属 class 启动就自动运行。在这份源码中，SurfaceFlinger 初始化属性时重置 service.bootanim.exit 和进度，并写入 ctl.start=bootanim，由 init 启动动画进程（也受 debug.sf.boot_animation 等配置控制）。

bootanimation 等待 SurfaceFlinger 服务可用，再创建显示图层并播放动画。它定期检查 service.bootanim.exit；属性变为非零时调用 requestExit()，但动画内容仍可能有收尾帧，因此设置属性与进程退出不能视作同步事件。动画结束也不表示 HOME 已经显示，WMS 还要确认应等待的窗口、动画服务状态和显示策略。

4. systemReady() 如何发起 HOME

前一章的 SystemServer.startOtherServices() 会进入 AMS systemReady()。AMS 完成启动前进程清理、将 mProcessesReady 置为 true，并在回调之后开始启动应用。对于普通的非 headless system user，关键入口是：

ATMS 的 RootWindowContainer.startHomeOnTaskDisplayArea() 为主显示区域生成 HOME Intent、解析符合条件的 Home Activity，并交给 ActivityStartController.startHomeActivity()。默认入口通常带 ACTION_MAIN 与 CATEGORY_HOME。若对应进程尚不存在，后续由 AMS/ProcessList 请求 Zygote 创建进程，再经过 ActivityThread 启动 Activity、创建窗口并绘制首帧；进程创建细节见《06-App进程》。

这里的“HOME”是系统要启动的 Activity 类型，并不保证画面一定是常见手机 Launcher。设置向导、用户选择的桌面、车机或电视的 Home，以及 headless system user、多显示屏场景都会改变解析和启动路径。当前源码还允许主题叠加准备阶段延迟 HOME 启动，所以不能把 systemReady() 等同于 Launcher onCreate() 已执行。

5. WMS 如何结束动画并启用显示

当 Activity 启动并进入 idle，ActivityTaskSupervisor.checkFinishBootingLocked() 会通过 ActivityTaskManagerService.postFinishBooting() 安排两项工作：请求 AMS finishBooting()，以及调用 WMS enableScreenAfterBoot()。异常情况下也可能通过 ensureBootCompleted() 走到这一阶段；不要把“HOME idle”写成唯一入口。

WMS 的 performEnableScreen() 会检查显示策略和应等待的系统窗口。条件满足后，它先将 service.bootanim.exit 设为 1，再轮询 bootanimation service 是否已经结束。确认动画结束后，WMS 调用 SurfaceControl.bootFinished()，通过 Binder 通知 SurfaceFlinger；随后标记显示已启用、打开输入分发，并通知 AMS bootAnimationComplete()。

SurfaceFlinger::bootFinished() 也会将 service.bootanim.exit 设为 1，并切换自身的启动期状态。WMS 另有启动超时的强制显示路径，所以实际设备上“屏幕亮起”“动画进程退出”“桌面首帧可见”不应被当作绝对相同的检查点。

6. BOOT_COMPLETED 到底在哪里发生

ActivityManagerService.finishBooting() 首先等待 mBootAnimationComplete；如果动画尚未结束，就记录待完成状态，等 WMS 的 bootAnimationComplete() 回调后继续。随后它通知 Zygote/ART、推进 SystemService.PHASE_BOOT_COMPLETED，设置 sys.boot_completed=1 和 dev.bootcomplete=1，并调用 UserController.onBootComplete() 开放用户解锁与后续广播流程。

这又分成三个概念：

  1. boot phase：PHASE_BOOT_COMPLETED 是 system_server 向 SystemService 发出的生命周期回调。
  2. 系统属性：sys.boot_completed=1 是设备级状态，也可触发 init 的属性 action。
  3. 广播：ACTION_LOCKED_BOOT_COMPLETED 与 ACTION_BOOT_COMPLETED 按用户状态分别投递。后者要等用户凭据加密存储可用，并由 UserController 安排；其投递和接收者执行是异步的。锁屏、次要用户、headless system user 等情况下，它与属性变为 1 的时间可能相差很远。

因此，排障时看到 getprop sys.boot_completed 为 1，只说明 AMS 到达设备级完成点，不能证明某个用户已经解锁、某个接收者已经处理完广播，也不能证明桌面一定可交互。

7. 用四组证据定位卡点

现象 优先检查 关键边界
一直黑屏或没有动画 getprop init.svc.surfaceflinger、getprop init.svc.bootanim、SurfaceFlinger/bootanimation 日志 SurfaceFlinger 注册、动画进程与显示设备
动画一直不退出 getprop service.bootanim.exit、dumpsys window、WMS performEnableScreen 日志 系统窗口/策略是否满足，动画进程是否响应退出
动画退出后没有 HOME dumpsys activity activities、dumpsys window、ActivityTaskManager/ActivityManager 日志 HOME 解析、进程启动、首帧绘制
属性已为 1 但应用没收到广播 getprop sys.boot_completed、用户解锁状态、ActivityManager 广播日志 设备级完成与用户级广播的差别

读取 Perfetto 时，可以把 SurfaceFlinger/bootanimation 的时间线，与 Start proc、HOME Activity 启动、wm_boot_animation_done、FinishBooting 放在同一条时间轴上。先判断卡在显示线还是应用线，再追具体进程和调用边界。

8. 小结

SurfaceFlinger 和 bootanimation 是 init 管理的独立 native 进程；HOME 是 ATMS 发起的 Activity；WMS 负责在窗口可显示时退出动画、通知 SurfaceFlinger 并启用显示；AMS 在动画完成后推进 PHASE_BOOT_COMPLETED、设置完成属性，再由 UserController 按用户状态投递开机广播。这些事件彼此有关，但不能互相替代作为“系统启动完成”的证据。
