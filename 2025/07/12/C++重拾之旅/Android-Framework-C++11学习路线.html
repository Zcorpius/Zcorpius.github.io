《C++ 重拾之旅》重组与 Android Framework C++11 学习路线

配套原文：C++重拾之旅.md。本文是阅读、修订和练习清单，不替代原文，也不默认原文的每个结论都正确。

目标：能读懂并讲清 Android Framework 中的 C++ 代码，重点覆盖 Binder、AMS、WMS、AudioTrack、AudioFlinger、AudioPolicy；能写、调试相应的 C++11 代码，并应对围绕这些模块的面试。预计按每周 8～10 小时投入，走完主线需约 7 周；已有基础时可以压缩。

一、先确定学习边界

  • 语言标准以 C++11 为准。 示例统一用 -std=c++11 编译；原文中的 decltype(auto) 属于 C++14，不能算 C++11 必学项。std::make_unique 也是 C++14，C++11 练习中不用它。
  • 源码以同一个 Android 分支为准。 先选面试或工作对应的 Android 版本，再在该分支内追调用链。下文的 AOSP 链接是入口；main 分支可能使用比 C++11 更新的语言特性，也可能与目标版本的类名、文件路径不同。
  • 学习深度以“会解释代码行为”为准。 每个主题都要回答：对象由谁创建、由谁持有、在哪个线程调用、跨了什么进程、错误如何返回、在哪里释放。
  • AMS/WMS 的 C++ 学习边界要明确。 它们主要由 Java 侧管理，C++ 重点是 Binder、JNI、Surface/图形和音频等跨语言、跨进程边界；不必把 AMS/WMS 的 Java 业务逻辑强行归到 C++ 章节。

二、原文 16 章：内容对应与阅读优先级

三、字符串、向量和数组 实际主要是数组/指针、初始化、strlen/sizeof 选读 重点是数组退化、缓冲区边界和字节数；string/vector 的主体在第七章。建议将本章标题调整为“数组、指针与 C 字符串”，避免标题承诺与正文不符。

五、类 构造、初始化列表、static、访问控制、explicit、对象大小、this、拷贝赋值 精读 Binder 接口、Track、PlaybackThread 都是类体系。重点是构造/析构、成员初始化顺序、explicit、拷贝与赋值、访问控制。对象大小和内存布局不要背成跨平台定律。

三、按实际工作重排的学习路径

阶段 0：摸底，半天到 1 天

  1. 用 c++ -std=c++11 -Wall -Wextra -pedantic 编译一个小程序：定义抽象基类、派生类、虚析构、std::vector、std::unique_ptr 和一个 lambda。
  2. 不查资料解释：T*、T&、const T& 的传参差别；new[] 与 delete[]；拷贝构造与拷贝赋值；sp<T> 大致解决什么问题。
  3. 对答不上来的点标记为“生疏”，后续阶段只在对应章节补，不从头逐字读。

完成标准：程序编译并运行；能指出每个对象何时构造、析构以及谁持有它。

阶段 1：语言和类，约 8～10 小时

阅读顺序：二 → 三的数组/边界部分 → 四的传参/回调部分 → 五。

必须掌握：指针与引用、const、nullptr、auto、constexpr、强制转换、初始化列表与成员初始化顺序、explicit、值传递与引用传递、函数指针和 lambda。保留 C++11 范围内的知识；decltype(auto) 等新版语法另记。

练习：写一个 Buffer 类，封装一段字节数据；提供只读访问、长度、边界检查；用 const Buffer& 传参；写一个回调函数处理数据；解释返回内部指针后的有效期。

完成标准：能对源码中的一个函数签名逐项说明对象是否被复制、能否为空、能否修改、调用完成后是否仍有效。

阶段 2：所有权与多态，约 8～10 小时

阅读顺序：十的语义部分 → 十一 → 十二 → 十五；十三只补足读模板类型的能力。

必须补充：

  • RAII 与特殊成员函数：构造成功后谁负责释放；析构和异常/提前返回；拷贝与移动的区别；Rule of Three/Five/Zero；= delete；继承类是否需要虚析构。
  • C++11 标准智能指针：unique_ptr 表示独占所有权，shared_ptr/weak_ptr 表示共享与弱观察；说明引用循环、裸指针借用与所有权转移。C++11 没有 make_unique。
  • Android 引用计数：读 RefBase、sp<T>、wp<T>，理解强/弱引用及死亡通知；不要把它们当作 shared_ptr/weak_ptr 的同名替代品，更不要未经检查混用不同所有权机制。以所选分支的类型约束和创建方式为准。

练习：画出每个对象的所有权图；写一个抽象接口与派生实现，用基类指针删除对象，解释为什么需要虚析构。

完成标准：看到 sp<Track>、wp<Client>、原始指针和引用时，能写出“持有/借用/可能为空/跨线程”四项判断，遇到不确定的地方能沿构造和赋值路径追查。

阶段 2.5：C++11 并发与线程，约 7～9 小时

原文没有独立的并发章节。这里要单独补齐，再进入 Binder 和 AudioFlinger 源码。

学习顺序 C++11 必会内容 对应 Framework 问题
1. 线程生命周期 std::thread 的启动、join/detach、对象与捕获变量的存活时间；安全退出和线程回收。 Binder 工作线程和音频工作线程何时创建、停止？回调是否可能访问已释放对象？
2. 数据竞争与互斥 共享状态的读写、数据竞争的未定义行为；std::mutex、std::lock_guard、std::unique_lock；锁保护的是哪一组状态。 Track 状态、客户端列表和策略状态由哪把锁保护？读写是否都遵守约定？
3. 等待与通知 std::condition_variable 配合谓词循环等待；虚假唤醒、丢失通知、停止标志。 PlaybackThread 没有可处理数据时如何等待与唤醒？退出时如何避免永久等待？
4. 原子操作 std::atomic 适合简单共享状态；先理解默认顺序，再按源码需要学习 acquire/release；volatile 不提供线程同步。 状态标志为何用原子量？多个相关字段是否还需要锁保证一致性？
5. 死锁与延迟 固定锁顺序、避免持锁做耗时调用、回调或跨进程 Binder 调用；认识优先级反转。 服务端回调重入、音频实时线程被低优先级线程持锁阻塞时会怎样？

练习：用 C++11 写一个有容量上限的生产者—消费者队列：多个生产者、一个消费者，condition_variable 等待，停止时唤醒所有线程并 join；说明每个共享字段由哪把锁保护。再画一个“两把锁顺序相反”的死锁例子，写出统一加锁顺序。

完成标准：能区分“线程安全的单个操作”和“多个操作组成的事务”；能画出线程、锁、条件变量、回调的关系图；能解释为什么 volatile、仅增加 sp 强引用或给单个字段加 atomic 都不能自动解决整个并发问题。

阶段 3：容器与算法，约 5～7 小时

阅读顺序：七 → 九 → 八。

必须掌握：vector 扩容及迭代器/引用失效；string 与 C 字符串边界；map、unordered_map 的查找和插入；sort、find、remove/erase、unique；lambda 按值/按引用捕获的生命周期。

练习：用容器管理若干“会话”，按 ID 查找、删除、遍历；故意在遍历中插入/删除并修正失效问题；说明为何不能把某个 STL 规则直接套用到 AOSP 自有容器。

完成标准：能解释一段容器操作的复杂度、是否会导致重分配，以及持有的指针是否还有效。

阶段 4：Binder、JNI 与 AMS/WMS 交界，约 9～11 小时

推荐追踪路线：选定 AOSP 分支中的一个服务调用，先画“调用方进程 → 生成的代理/接口 → Binder 驱动 → 服务端线程 → 实现对象”；再找它与 Java 侧交界处的 JNI 或 Java Binder 接口。不同接口可能使用 Java、CPP 或 NDK AIDL 后端，先查接口和生成代码再下结论。

需要补充：

主题 必须回答的问题 动手产出
AIDL 与 Binder 代理和服务端接口如何生成？Parcel 中传什么？同步调用、oneway、错误返回有什么差别？ 一张从调用方到服务端实现的调用图，标出跨进程边界。
Binder 线程 ProcessState/IPCThreadState 和线程池分别做什么？服务端回调是否并发？持锁跨 Binder 调用会怎样？ 为一个接口标注线程、锁和可能的重入点。
生命周期 远端对象/客户端退出后如何感知？死亡通知如何清理状态？ 一张含强/弱引用和死亡回调的所有权图。
JNI JNIEnv* 属于哪个线程？local/global reference 何时失效？native 对象句柄如何保存和释放？ 沿一个 Java → JNI → C++ 方法记下引用的创建和删除。
AMS/WMS 哪部分是 Java 业务控制，哪部分进入 native/Binder？传到 native 的对象与状态由谁负责？ 各选一个熟悉的 AMS/WMS 场景，写出边界和 C++ 参与点。

完成标准：能从源码说清“谁调用谁、在哪个线程和进程、对象怎么活到回调结束”，并能区分 libbinder 的 CPP 后端与 libbinder_ndk 的 NDK 后端。

阶段 5：AudioTrack、AudioFlinger、AudioPolicy，约 10～12 小时

先选一条普通播放路径，例如 Java AudioTrack 播放 PCM；不要在第一遍同时展开 offload、MMAP、AAudio、录音和蓝牙等分支。下图只表示追踪顺序，具体调用和线程以所选分支源码为准：

Java AudioTrack
  → JNI 桥接
  → native AudioTrack / AudioSystem
  ├─ 控制与策略：AudioPolicyService → AudioPolicyManager → 输出/设备选择
  └─ 播放与数据：Binder 接口 → AudioFlinger → Track / PlaybackThread → Audio HAL

读源码时逐层记录：

  1. Java 创建/播放/释放如何进入 JNI；JNI 保存什么 native 状态，何时清理。
  2. native AudioTrack 如何创建 Track、提交音频数据或共享缓冲区；哪些调用跨 Binder，哪些留在本进程。
  3. AudioFlinger 如何创建/持有 Track，PlaybackThread 如何取数据、混音与向 HAL 提交；线程与锁在哪里切换。
  4. AudioPolicyService/AudioPolicyManager 如何参与输出与设备选择；把“策略控制”与“实际搬运音频数据”分开追。
  5. 遇到 sp/wp、回调、共享内存、状态码、等待/唤醒时，记录所有权、生命周期、可能的 underrun 和失败清理路径。

完成标准：独立画出播放链路，标出实际遇到的进程与线程边界，以及三个关键对象的生命周期；能回答“为什么无声/卡顿可能是策略、Track 状态、线程调度或 HAL 任一环节造成的”。

阶段 6：调试与面试闭环，约 6～8 小时

  • 选一个能复现或已有记录的 native 问题：崩溃、泄漏、死锁、无声或播放卡顿。按“现象 → 日志/堆栈 → 所属进程和线程 → 对象生命周期/锁/状态 → 根因 → 修复验证”记录。
  • 练习读 native crash 的 tombstone：崩溃线程、signal、backtrace、寄存器和相关对象；用对应构建产物进行符号化。音频问题配合 dumpsys media.audio_flinger、音频策略 dump、logcat 和 Perfetto 等工具，实际可用命令以设备版本为准。
  • 做两轮口述：第一轮 15 分钟讲 C++11 生命周期与多态；第二轮 20 分钟讲 Binder + 音频调用链，要求边画图边说线程和错误路径。

完成标准：最终留下三份材料：一页 C++11 所有权速查表、一页 Binder 调用与线程图、一页普通播放调用链和排障记录。

五、原文之外必须补的内容

六、原文中的结论：先核验，再记忆

这些点建议在修订原文时逐条用 C++11 最小示例验证；下面的“纠正方向”可以作为勘误清单。

原文位置/主题 需要修正或限定的结论 正确的学习方式
二：野指针/悬空指针 空指针解引用不保证得到编译错误；释放对象后，其他别名不会自动置空。 把非法解引用视为未定义行为，追每一个别名的有效期。
二：dynamic_cast 向下转换的运行时检查及失败行为不能说反。 以有虚函数的多态基类做指针/引用转换实验，分别观察失败结果。
二：decltype(auto) 它不是 C++11。 C++11 主线只保留 auto、decltype；新版特性单独标注标准版本。
三：拷贝初始化 不能说“总会调用拷贝构造”；C++11 中可能发生移动或允许的拷贝消除。 给拷贝、移动构造打印日志，并说明观察结果也受编译器优化影响。
五：静态成员 “静态成员只能在类外初始化/定义”过于绝对；把非 inline 定义放在头文件还可能造成多重定义。 区分 C++11 允许的类内初始化情形、ODR 使用和类外定义。
五：volatile 它不能当线程同步手段。 并发共享状态使用互斥锁或 std::atomic，按实际内存顺序需求选用。
七：vector::capacity() 与 resize() capacity 是当前可容纳元素总数，不是“剩余空间”；resize 可能触发扩容。 分开记录 size、capacity、迭代器/指针是否失效。
十：new/delete 与 malloc/free 交叉配对释放不合法，不能写成“理论上可以”。 new 配 delete，new[] 配 delete[]，malloc 配 free。
十一：字符串与拷贝示例 new char(20) 只创建一个 char；原示例还存在重复变量名/未声明函数等编译问题。 先用 -std=c++11 -Wall -Wextra -pedantic 编译，再讨论深拷贝和返回值优化。
十三：模板示例 有未定义标识符，不能直接当可运行代码记。 修到最小可编译例子，再理解模板实例化。
十四：动态异常规格 throw(int) 等写法在 C++11 中仍可用但已弃用。 知道其历史语义即可，实际代码优先学习 C++11 的 noexcept。
十六：端序示例 把整数强转成 char 不等于查看对象内存的第一个字节。 用 unsigned char 读取对象表示，并说明结论限定在具体平台。
十二/十六：虚函数与 inline “虚函数不能是 inline”不成立；原文相邻章节也有冲突。 区分“可以声明 inline”和“经虚分派调用时能否被内联优化”。
十二：vptr/虚表布局 vptr 的位置、大小和初始化细节不是 C++ 标准的统一承诺。 面试先讲多态语义，再说明具体布局依赖 ABI 和编译器。

每题都尽量附一个源码位置、对象关系或最小代码，避免只背概念。

  4. std::shared_ptr 与 sp<T> 有什么共同目标和不同约束？wp<T> 升级为强引用时要考虑什么？
  5. 为什么通过基类指针销毁派生对象需要虚析构？override 能帮你发现什么错误？
  6. vector 扩容后，原来的元素指针和迭代器还能不能用？遍历时删除元素如何写？
  7. 条件变量为什么要带谓词等待？退出线程时如何唤醒等待者？原子标志能否替代保护多个字段的互斥锁？
